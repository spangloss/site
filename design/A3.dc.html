SECURITY LABELS FOR AI AGENT TELEMETRY

Your agent’s actions, glossed.

Spangloss reads each tool call in an AI agent’s OpenTelemetry trace and writes a short, typed gloss beside it: what the call did, what data it touched, whether its output tried to steer the agent, and how sure it is. Detections and audits run over the glosses, not raw prompts.

How it works

A Python sidecar beside your OpenTelemetry pipeline. Detective, not preventive: it never blocks an agent action.

I.

Capture

Agent traces and log events arrive over OTLP. Account identity is stripped before anything touches disk.

II.

Parse

One record per tool call: arguments rebuilt from every copy the telemetry keeps, the evidence available, and nesting under subagents.

III.

Derive & ask

Structural facts are computed. A decision model, local or hosted, answers only the judgments, through narrow typed questions.

IV.

Gloss

Answers go back as sec.* attributes, each with its probability, evidence basis, model and taxonomy version.

V.

Detect

Deterministic rules read the labels. Subagent taint, for one, follows untrusted content back through delegation.

PRINCIPLES

“Labels are facts; findings are rules.”

The model labels single calls. Session-level findings come from deterministic rules, never from the model.

“Derive what’s structural; ask only for judgment.”

If the trace already says it, compute it. Prompt notes shift probabilities; they rarely change answers.

“Untrusted text is evidence, never instruction.”

Tool output sits in marked evidence fields, and never reaches a structural question it could steer.

“Detective, not preventive.”

A wrong label costs an analyst minutes, not a broken workflow. That makes it a safe first home for decision models.

The labels

Taxonomy v0.3.2, draft. Small answer sets and no abstain answer: uncertainty shows up as a low probability. A label is asked only when the call carries the evidence it needs.

Some answers are derived, not asked: a subagent spawn is never itself a source or a sink, and where a loaded tool comes from is read from its server name.

What agent telemetry doesn’t show

Five gaps in Claude Code 2.1.312’s OpenTelemetry output, each observed while building spangloss. Every one limits what any monitoring built on these traces can see.

Evidence and method ↗
  1. 1

    Long arguments are cut to 128 characters in the logs

    Any argument over 512 characters keeps only its first 128. Shell commands survive whole on the span; subagent prompts and edit strings survive nowhere.

  2. 2

    Search results are never captured

    Grep and Glob calls record what the agent searched for, never what it found.

  3. 3

    A web fetch returns a summary, not the page

    Planted instructions were dropped or reduced to a one-line warning: a partial defense that also hides the attempt.

  4. 4

    What a subagent hands back often goes unrecorded

    In headless runs, no handback appears at all, so returned text can’t be checked.

  5. 5

    MCP tool descriptions never appear

    A poisoned tool description is invisible to monitoring built on these traces.

How we evaluate

Every label is scored against hand-checked reference labels, the gold set. Results are published with v0.

Real sessions

Tool calls from actual agent work, labeled by hand under the written taxonomy.

Seeded scenarios

Scripted agent runs in isolated containers, with fake secrets and planted canaries. Expected labels are written first, so gold comes by construction.

Honest scoring

Accuracy with 95% intervals, per call and per unique call shape, plus calibration: does a p of 0.9 mean right nine times in ten?

Two kinds of model

A hosted decision model and a local open one, run on the same calls, so the trade-off is measured, not guessed.
